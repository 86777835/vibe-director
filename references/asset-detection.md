# 动态资产检测规则

> 用于 Mode A 写剧本 / Mode B 解析剧本 / Mode D 导入素材 时，agent 自动识别**新出现但 wiki 中无卡片**的实体，决定是否自动建 stub 卡。
> 触发时机：每次写完一集剧本 / 解析完一段素材 / 用户主动 `/盘点`。

---

## 检测算法

### Step 1：实体抽取
用 LLM 从目标文本中提取所有**命名实体**：
- 人名：可识别的姓氏+名字组合（"露西·陈"、"张医生"），排除代词（"她"、"那人"）
- 地点名：明确命名的场所（"废弃图书馆"），排除泛指（"地下室"无前缀）
- 物品名：有专名或定语的关键物（"古老药剂瓶"），排除普通物（"咖啡"）

### Step 2：对照 index.md
对每个实体查 `index.md`：
- 已存在 → 跳过
- 不存在 → 进入阈值判断

### Step 3：阈值判断

| 信号 | 自动建 stub？ |
|------|-------------|
| 命名实体 + 出现 ≥ 2 次 | ✅ 是 |
| 命名实体 + 1 次 + 剧本明确标"核心场景/关键道具" | ✅ 是 |
| 命名实体 + 1 次 + 普通提及 | ❌ 否（保持文本提及） |
| 不命名（"路人"、"一个男人"、"那张椅子"）| ❌ 否 |
| 用户明确说"X 是新角色/场景/道具" | ✅ 是（不需阈值）|

### Step 4：分类
对每个待建 stub，判断类型 → 决定目标目录：

| 类型信号 | 目录 |
|---------|------|
| 人名 + 有动作/对白 | `01_资产/01_角色/` |
| 地点名 + 场景描述（如 INT./EXT. 标签）| `01_资产/02_场景/` |
| 物品名 + 情节作用 | `01_资产/03_道具/` |
| 时间事件 | 追加到 `02_故事/完整时间线.md`，不建独立卡 |

## 自动建卡流程（推荐配置 A）

1. **写完目标文本**（如第 N 集剧本）
2. **抽取 + 对照 + 阈值** → 得到 stub 候选列表
3. **批量创建 stub 卡**（使用 `asset-card-template.md` 的 stub 模板）
4. **同步更新 `index.md`**（追加新条目，标注 status: stub）
5. **写 log.md**：`[asset-detect] 第 N 集检测新增 X 角色 + Y 场景 + Z 道具`
6. **告知用户**：

```
✅ 第 21 集剧本已写完（1240 字）

📌 检测到 3 个新资产（已自动建 stub 卡）：
   - 👤 角色：露西·陈（出现 2 次，副警长助理）→ stub
   - 🏛️ 场景：废弃图书馆（整集核心）→ stub
   - 📦 道具：古老药剂瓶（情节核心）→ stub
   
要现在补全详情吗？
[A] 补全（agent 引导填字段 → 出参考图）
[B] 先放着（status 保持 stub，后续 lint 会提醒）
[C] 撤销建卡（说明：哪个不需要建？）
```

## 跨集追溯（推荐配置 A）

新增资产时，agent **回查前面集数**，找泛指可能就是新资产的句子：

```
agent: 你刚加了"露西·陈"（副警长助理）。
       我检索了前面集数，发现以下泛指句可能是她：
       
       - 第 17 集 P04："副警长助理快进来一下" — 1 处
       - 第 19 集 P02："助理把档案放在桌上" — 1 处
       
       要不要把这些回填为"露西"？这会让前后连贯。
       [A] 全部回填  [B] 只回填第 17 集那处  [C] 都不改  [D] 我看看上下文再说
```

回填走 §十三.2 修改类草案模式（影响分析 → 用户审批 → 多文件 Edit）。

## Stub 卡未补全时的提醒（推荐配置 A）

**不阻止后续操作**，但在视觉生成时主动提示：

```
你：为第 21 集 P03 出故事板

agent：[读 P03 beat，发现需要 露西·陈 + 废弃图书馆 的参考图]
       
       ⚠️ 露西·陈 卡片是 stub，外貌字段为 TODO
       ⚠️ 废弃图书馆 卡片是 stub，无场景描述细节
       
       两个选择：
       [A] 我先帮你补一下外貌/场景描述（5 分钟）然后出图
       [B] 直接用 LLM 即兴生成（可能偏离你想要的风格，但快）
       [C] 我先生成 stub 角色/场景参考图（用现有线索 + 默认风格）→ 后续可迭代
       
你：C

agent：[/配图 露西·陈 + /配图 废弃图书馆 → 参考图就位]
       [继续出第 21 集 P03 故事板]
       
       已生成参考图。露西的外貌字段已更新（按生成图反推）。
       要不要看看？
```

## 状态字段（status）

每张卡片的 frontmatter 含 `status` 字段：

| status | 含义 | 视觉资产可用？ |
|--------|------|------------|
| `stub` | 仅命名 + 出场记录 | ⚠️ 出图前提示用户补全 |
| `partial` | 部分字段完成（如外貌完成但性格 TODO） | ✅ 出图可用 |
| `complete` | 所有字段完成 | ✅ 出图可用 |
| `with-image` | 有参考图（任何 status 都可叠加这个标签） | ✅ |

`/lint` 按 status 分组报告，提示哪些可以推进。

## 命名规范

新建卡片文件名：
- 角色：`{中文名}.md`（如 `露西·陈.md`）
- 场景：`{中文名}.md`（如 `废弃图书馆.md`）
- 道具：`{中文名}.md`（如 `古老药剂瓶.md`）

英文名（用于图片路径）：
- 由 agent 自动转写或问用户
- 用于 `images/{english_slug}.png`
- 例：`露西·陈` → `lucy_chen.png`

## 边界情况

### 同名实体冲突
用户已有"露西·陈"卡片（艾拉拉的妹妹），剧本中又出现"露西"（副警长助理）：
- agent 优先**全名匹配**："露西·陈" → 已存在卡片
- 仅出现"露西" → agent 反问"是已有的露西·陈吗？还是新角色？"

### 别名/代号
"格雷森镇长" 在剧本中可能写作"镇长"。识别规则：
- 角色卡 frontmatter 可包含 `aliases: [镇长, 哈罗德]`
- agent 检测时把别名也算作"已存在"

### 一次性背景
"凯文走过一辆黑色凯迪拉克" — 凯迪拉克是普通描述，不建卡。
判断：是否在 ≥2 集出现，是否情节相关。

### 临时变体
"暴风雪夜的旅馆" vs "白天的旅馆"——不是新场景，是已有"汽车旅馆"的时段变体。
处理：参考图按变体生成（如 `blackwood_inn_blizzard.png`），但**不**建新卡。

## 检测频次

| 触发 | 频次 |
|------|------|
| 写完每集剧本（Mode A 或 B） | 自动触发 |
| 解析 raw/ 素材（Mode D） | 自动触发 |
| 用户 `/盘点` | 显式触发，全 wiki 扫 |
| `/lint` 跑时 | 作为子项，列 dangling references |

---

## 例外（不自动建卡）

以下情况 agent **不要**自动建 stub：
- 用户明确说"这个不要建卡"
- 实体名含 `(临时)` `(草稿)` `(tbd)` 等标记
- 实体是已知别名（在 `aliases` 字段中）
- 实体是已知冻结版本（如 v1.0 中的角色，不在 v2.0 active 中新建）

## 配置文件（可调）

阈值参数存在 `preferences.md` 的"资产检测"段：

```markdown
## 资产检测偏好

- 自动建卡阈值：出现次数 >= 2（默认）
- 跨集追溯：开启（默认）
- Stub 卡提醒：出图前提醒（默认）
- 普通物品忽略：开启（默认）
```

用户可调，例如严格模式："出现次数 >= 1 就建，宁滥勿缺"。
