# 方向词典 — 重构 Patch 映射

> 用户口述方向词 → 编译为命名 patch 集 → agent 应用到 fork 的新 wiki。
> 此文件是 Mode E 的核心规则书。

---

## 怎么用

1. 用户说："**我想试试暗黑版，把主角改成女性，节奏更快**"
2. Agent 解析关键词："暗黑" + "主角性别" + "节奏更快"
3. 查本词典 → 三个 patch：
   - `tone-darken`
   - `protagonist-gender-swap`
   - `pacing-faster`
4. 每个 patch 的"影响范围"决定要改哪些文件
5. 走 §十三.2 草案模式逐 patch 应用

---

## Patch 集合

### 调性类（Tone）

#### `tone-darken` — 更暗黑
**触发词**：暗黑、更黑、压抑、阴郁、绝望、Nordic noir、不留希望

**影响范围**：
| 文件类型 | 改什么 |
|---------|--------|
| 角色卡 | 性格描述减弱"温暖/善良"，加强"冷漠/创伤/绝望" |
| 角色目标 | 从"救赎/团聚"改为"复仇/解构/同归于尽" |
| 剧本对白 | 减少幽默 beat，减少安抚台词，缩短句子 |
| 剧本结构 | 删除轻松过场，加重 cliffhanger |
| 世界观 | 加入"系统性恶意 / 无解循环 / 历史诅咒"元素 |
| 色彩脚本 | 高对比黑白 / 冷蓝 / 暗红，去除暖色 |
| 视觉风格 | 阴影更重，自然光为主，避免亮丽特效 |

**保持不变**：核心剧情骨架、主要角色关系、关键转折点

---

#### `tone-lighten` — 更轻松
**触发词**：轻松、明快、温暖、治愈、加点幽默、less heavy

**影响范围**：
- 角色：增加"幽默"、"乐观"、"傻气"特质
- 对白：加入俏皮台词 / 内心吐槽
- 结构：插入轻松 beat 缓冲严肃段落
- 色彩：偏暖、饱和度提升
- 配乐建议：从压抑/紧张 → 跳跃/抒情

---

#### `tone-add-humor` — 增加幽默元素（局部）
**触发词**：加点幽默、不要太严肃、加 comic relief

**影响范围**：相比 `tone-lighten` 更轻量——只插入 2-3 个幽默 beat / 角色，不动整体调性。

---

### 角色类（Character）

#### `protagonist-gender-swap` — 主角性别互换
**触发词**：主角改成女/男、换女主、性转

**影响范围**：
| 文件类型 | 改什么 |
|---------|--------|
| 角色卡 | 性别字段；姓名（如需要本土化）；外貌描述全套 |
| 角色关系 | 所有"他/她"指代翻转 |
| 剧本对白 | 涉及主角的所有"他/她"称谓；与性别相关的台词（如"作为一个男人..."）|
| 视觉资产 | 所有 manifest 标 needs_regen（参考图需重生）|
| 世界观 | 如有性别相关规则（如"只有男人能..."），需重新定义 |

**保持不变**：角色性格内核（除非用户额外指定）、剧情骨架

⚠️ 高影响 patch，全 wiki 大范围改动。

---

#### `protagonist-job-change` — 主角职业改变
**触发词**：把记者改成医生、换职业、从XX变成YY

**影响范围**：
- 角色卡：职业字段、相关背景（学历/经历）、入局动机
- 剧本：所有专业领域台词 / 道具
- 道具：职业相关道具替换（笔记本电脑 → 听诊器等）

---

#### `protagonist-age-shift` — 主角年龄段调整
**触发词**：主角再年轻点 / 老一点、改成 30 岁

**影响范围**：
- 角色卡：年龄 + 外貌（视觉变化）
- 关系网：可能影响"前辈/后辈"称谓
- 剧本：年龄相关台词

---

### 设定类（Setting）

#### `setting-time-shift` — 时空背景调整
**触发词**：背景改到 X 年、年代转换、放到 X 时代

**影响范围**：
| 文件类型 | 改什么 |
|---------|--------|
| 世界观 | 时空背景段全部重写 |
| 场景卡 | 建筑/装潢/科技程度 |
| 道具 | 时代符合（手机？BB机？固话？）|
| 剧本 | 涉及时代的台词、参照物、文化梗 |
| 视觉 | 全部场景图标 needs_regen |

⚠️ 极高影响 patch，几乎触及所有视觉资产。

---

#### `setting-location-shift` — 地理位置调整
**触发词**：背景从美国搬到中国、换城市、设定到 X 地

**影响范围**：
- 世界观：地理设定段
- 场景卡：建筑风格 / 自然环境
- 角色：姓名本土化、口音/方言、文化习俗
- 剧本：地名、文化梗、节日

---

### 题材类（Genre）

#### `genre-strip-romance` — 去掉感情线
**触发词**：去掉感情戏、不要爱情、纯 X 向

**影响范围**：
- 角色关系：相关爱人关系改为"朋友/同事/陌生人"
- 剧本：感情戏 beat 删除或改为其他冲突
- 分集目录：感情转折节点重新设计

---

#### `genre-add-mystery` — 加入悬疑元素
**触发词**：加点悬疑、变成推理向、有 mystery 元素

**影响范围**：
- 世界观：埋入未解之谜
- 角色：增加"信息差"角色（知情不报的）
- 剧本：每集留一个小钩子，最终集大揭秘

---

#### `genre-shift-{X}-to-{Y}` — 大题材切换
**触发词**：从浪漫变悬疑、把这个浪漫剧改成恐怖

**影响范围**：极高——几乎触及全部内容。Agent 应**强烈建议**做完整 fork 而不是局部修改，并预警用户"这接近从头创作"。

---

### 节奏类（Pacing）

#### `pacing-faster` — 节奏更快
**触发词**：节奏快一点、紧凑、不要拖、删掉慢戏

**影响范围**：
- 分集目录：每集 beat 数减少
- 剧本：去掉过场、压缩对话
- 卡点：付费卡点前移
- 视觉：长镜头改为短切

---

#### `pacing-slower` — 节奏更慢
**触发词**：慢一点、有呼吸感、情绪戏多一点

**影响范围**：相反方向。增加情绪过场、内心独白、留白。

---

### 结构类（Structure）

#### `structure-restructure-plot` — 剧情骨架重排
**触发词**：把 X 转折前移、节点重新设计、整集顺序换一下

**影响范围**：
- 分集目录：beat 顺序重新设计
- 剧本：每集开场/结尾位置调整
- 时间线：可能需要更新（如倒叙结构变正叙）

---

#### `structure-pov-shift` — 视角变换
**触发词**：换成 X 的视角、改成多视角、用第一人称

**影响范围**：
- POV设定：核心视角文件重写
- 03_视角/ 全部"观众已知"重新计算
- 剧本：信息呈现顺序 / 限制重新设计

---

### 元类（Meta）

#### `full-restructure` — 完全重构
**触发词**：从头来 / 完全重构 / 大改特改

**特殊处理**：
1. agent 必须**强烈反问**："这接近重做一遍，要不要直接 Mode A 新项目？还是确实想保留世界观/角色名等元素？"
2. 如用户坚持 → 自动列出所有 patches，让用户挑选保留 vs 替换
3. 实质上变成"半 Mode A"

---

## 组合规则

### 可叠加（无冲突）

```
tone-darken + protagonist-gender-swap = 暗黑女主向
tone-lighten + pacing-faster = 轻快版
```

应用顺序：按 patch 列表顺序逐个走草案流程。

### 冲突 patch（agent 应警告）

| Patch A | Patch B | 冲突点 |
|---------|---------|--------|
| `tone-darken` | `tone-lighten` | 调性互斥 |
| `genre-strip-romance` | `genre-add-romance`（无此 patch）| 显然 |
| `pacing-faster` | `pacing-slower` | 节奏互斥 |

冲突时 agent 反问用户："你想要的是 A 还是 B？两个不能同时应用"。

---

## 未在词典中的方向

用户说一个词典里没有的方向词（如"加点赛博朋克味"），agent：
1. **不要硬编译**为已有 patch
2. **反问**用户具体含义："赛博朋克在你心里是什么样子？霓虹色调？反乌托邦设定？特定时代？"
3. 收集用户描述后，**临时定义**新 patch（如 `aesthetic-cyberpunk`），明确列出影响范围给用户审
4. 用户确认后，可以选择"是否把这个 patch 加入词典供以后复用"

---

## 词典扩展

新 patch 加入词典时必须包含：
- 触发词列表
- 影响范围表（哪种文件改什么）
- 保持不变的部分
- 与其他 patch 的冲突关系（如有）

agent 在用户确认后可以追加新 patch，但**不要静默修改已有 patch**——可能破坏旧 wiki 的可复现性。
